# 전체 상세 설계 프로그램

- **문서 ID**: PLAN-00
- **상태**: 동결
- **작성일**: 2026-08-24
- **구현 범위**: [전체 제품 구현 범위](../product/IMPLEMENTATION-SCOPE.md)
- **문서 목록·상태 정본**: [프로젝트 문서 지도](../DOCUMENT-MAP.md)

## 1. 목표

PRD 전체 범위를 한 개발 단계에서 구현할 수 있도록 제품·UX·아키텍처·도메인·데이터·
API·보안·품질·운영 문서를 먼저 완성한다. 이 문서는 개별 설계 내용을 합치지 않고 작성
순서와 전체 동결 게이트만 소유한다.

## 2. 설계 원칙

- 애플리케이션 코드는 문서 지도의 모든 필수 문서가 동결될 때까지 작성하지 않는다.
- 한 정책은 한 정본 문서가 소유하고 다른 문서는 링크한다.
- 타입, 상태 전이, 오류, 권한, 원자성과 idempotency를 구체적으로 정의한다.
- 정상 흐름과 함께 빈 상태, stale revision, 중복 요청, 부분 실패와 복구를 설계한다.
- 기술 선택은 요구 계약과 평가 기준을 먼저 작성한 뒤 개별 ADR로 확정한다.
- 설계에서 발견한 PRD·도메인 결함은 원본 문서를 먼저 수정한다.
- 중요한 제품·보안·아키텍처·UX 선택은 사용자 Decision Gate를 통과한다.

## 3. 작성 프로그램

```text
제품 문서 분해와 용어 확정
→ 정보 구조 + 시스템 Context
→ UX 흐름 + 시스템 기반 계약
→ 도메인 상세 Spec + 데이터 + API
→ 보안 + 품질 + 운영
→ 요구사항 추적성 + 구현 계획 + 위험 기록
→ 전체 모순·누락 검토
→ 설계 동결 보고서
→ 전체 제품 구현
```

순서는 정보 의존성을 나타낸다. 제품 범위를 나누거나 일부만 출시한다는 의미가 아니다.
중요한 사용자 결정은 여러 회차로 수집할 수 있다. 설계 본문은 하나의 전체 설계 태스크에서
동일한 결정 snapshot을 기준으로 일괄 작성하며 구현 진입도 전체 단위로 판정한다.

## 4. 사용자 Decision Gate

중요한 선택이 필요하면 영향받지 않는 조사와 문서 작업을 먼저 완료한다. 이후 상황,
대안, 영향과 권장안을 사용자에게 제시한다. 답을 태스크와 제품 Decision Register 및
관련 정본 문서에 기록하기 전에는 선택에 따라 달라지는 내용을 확정하지 않는다.

결정이 필요한 문서는 `결정 대기`로 표시한다. 그 문서를 의존하는 작업은 선택과 무관한
부분만 작성할 수 있다.

## 5. 개별 문서 완료 조건

- 소유하는 요구사항과 도메인 불변식이 연결되어 있다.
- 사용자 흐름과 상태 전이가 정상·예외 경로를 모두 포함한다.
- 저장 타입, API·event·job schema와 오류 코드가 구체적이다.
- 권한 검사가 데이터 접근보다 먼저 배치되어 있다.
- transaction, concurrency, idempotency와 failure recovery가 정의되어 있다.
- 보안·관측성·migration·성능 영향을 기록했다.
- 단위·계약·통합·E2E 테스트로 완료 조건을 증명할 수 있다.
- 미해결 질문이 없거나 구현에 영향을 주지 않는다는 근거가 있다.

## 6. 전체 설계 동결 게이트

- `DOCUMENT-MAP.md`의 필수 문서가 모두 `동결`이다.
- 요구사항 → 도메인 불변식 → 상세 설계 → 테스트의 추적 표가 완성됐다.
- 동일 개념의 중복 모델과 상충하는 상태·오류·권한 규칙이 없다.
- 외부 경계와 비동기 흐름에 timeout, retry, cancellation과 idempotency가 있다.
- Threat Model의 고위험 항목과 데이터 보존 정책이 설계에 반영됐다.
- 기술 선정 ADR이 전체 계약을 구현할 수 있음이 확인됐다.
- Repository Structure, Implementation Plan, Definition of Done과 Risk Register가 동결됐다.
- Design Freeze Report가 문서 누락과 모순이 없음을 확인했다.

## 7. 구현 이후 변경

AI를 이용해 설계와 구현을 빠르게 바꾸는 것을 제한하지 않는다. 변경 태스크에서 영향받는
제품·도메인·상세 설계·schema·migration·테스트를 코드와 함께 갱신해야 완료된다. 코드만
바뀐 상태는 빠른 완료가 아니라 문서·구현 불일치 결함이다.
