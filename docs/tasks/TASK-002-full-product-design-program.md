## 사용자 결정

### 결정 요청 1: 전체 구현에서 Group 권한 관리를 제공할 것인가

- **상황**: Permission Subject가 User와 Group을 수용해야 한다는 도메인 방향은 있지만,
  Group 생성·멤버 관리·권한 부여 UX까지 첫 구현에 포함할지는 확정되지 않았다.
- **대안과 영향**: 포함하면 팀 규모가 커져도 권한을 구조적으로 관리할 수 있지만
  Workspace·Permission UX와 테스트 범위가 커진다. 제외하면 내부 타입만 확장 가능하게
  두고 사용자별 권한만 제공하지만 첫 구현 범위가 PRD 전체라는 원칙과 긴장이 생긴다.
- **권장안**: Group 관리와 Group Permission을 전체 구현 범위에 포함한다.
- **사용자 결정**: 대기. 이 설계 프로그램의 구조에는 영향을 주지 않으므로 DEC-001로
  이관하고 Permission 상세 설계를 시작할 때 확인한다.

## 의사결정

### 결정 1: MVP를 두지 않고 PRD 전체를 첫 구현 범위로 삼는다

- **상황**: 일부 사용자 여정만 먼저 구현할지 전체 제품을 한 개발 단계에서 구현할지
  결정해야 한다.
- **검토한 대안**: MVP는 초기 검증 범위를 줄이지만 전체 도메인 계약이 뒤늦게 바뀔 수
  있다. 전체 구현은 설계량과 검증량이 크지만 AI를 통한 설계·구현 변경 비용이 낮고,
  사용자가 원하는 완전한 제품 경계를 처음부터 유지한다.
- **선택과 근거**: PRD의 모든 필수 요구사항을 첫 구현 범위로 삼는다. 비목표와 명시적인
  향후 후보만 제외한다.

### 결정 2: 설계는 분리 작성하되 전체 동결 후 구현한다

- **상황**: 모든 상세 구현을 한 문서에 담으면 빠르게 쓸 수 있지만 책임 경계와 모순을
  검토하기 어렵다.
- **검토한 대안**: 단일 대형 구현 명세 / 책임별 설계 문서 묶음. 전자는 탐색은 쉽지만
  변경 충돌과 중복이 커지고, 후자는 정본 경계와 검토 책임이 분명하다.
- **선택과 근거**: UX, 시스템, 도메인, 운영·검증 문서로 나누고 Master Plan에서 추적한다.
  모든 필수 문서가 동결될 때까지 애플리케이션 코드를 작성하지 않는다.

### 결정 3: 빠른 변경은 문서 생략이 아니라 동기화 비용 절감에 사용한다

- **상황**: AI를 사용하면 설계와 구현을 빠르게 바꿀 수 있으므로 문서 절차가 불필요한지
  판단해야 한다.
- **검토한 대안**: 코드를 먼저 바꾸고 문서를 추후 갱신하면 순간 속도는 빠르지만 정본이
  사라진다. 같은 태스크에서 설계와 코드를 함께 변경하면 속도를 유지하면서 계약을 보존한다.
- **선택과 근거**: 최초 구현 전에는 전체 설계를 동결한다. 구현 이후 변경은 해당 태스크에서
  정본 문서와 코드를 함께 갱신한다.

### 결정 4: 사용자 확인이 필요한 설계 선택은 Decision Gate로 관리한다

- **상황**: 전체 상세 설계를 작성하는 동안 제품과 아키텍처를 실질적으로 바꾸는 선택이
  반복해서 발생한다.
- **검토한 대안**: 에이전트가 합리적인 기본값을 선택하면 빠르지만 사용자 의도와 다른
  전체 설계를 만들 수 있다. 모든 세부사항을 질문하면 진행이 지나치게 자주 멈춘다.
- **선택과 근거**: 결과를 실질적으로 바꾸는 결정만 상황·대안·권장안과 함께 질문한다.
  결정 전에는 영향받지 않는 작업만 진행하고 답을 태스크와 정본 문서에 기록한다.

### 결정 5: 단일 PRD를 책임별 문서 체계로 분해한다

- **상황**: 전체 제품을 한 번에 설계하려면 하나의 PRD나 구현 명세에 제품·UX·데이터·
  API·보안·테스트·운영을 함께 넣을 경우 정본 경계와 변경 영향이 불명확해진다.
- **검토한 대안**: 단일 대형 문서는 처음 읽기 쉽지만 중복과 충돌이 커진다. 책임별 문서는
  파일 수가 늘지만 각 정책의 owner, 의존성, 검증 상태를 명확히 관리할 수 있다.
- **선택과 근거**: 일반 IT 제품의 생명주기에 필요한 문서를 제품, UX, 아키텍처, 도메인·
  데이터·API, 보안·품질·운영, 구현 계획으로 분리한다. `DOCUMENT-MAP.md`가 경로와 상태의
  단일 진실 소스다.
