## 의사결정

### 결정 1: 기존 구현을 보존하지 않고 설계 기준선부터 다시 만든다

- **상황**: 기존 저장소는 Git·로컬 데스크톱 중심의 이전 방향을 구현하고 있었고,
  최종 제품 대화는 웹·애플리케이션 데이터 모델 중심으로 변경됐다.
- **검토한 대안**: 기존 코드를 부분 재사용하면 초기 비용은 낮지만 폐기된 도메인
  가정이 새 설계에 남는다. 전체 초기화는 구현 자산을 잃지만 새로운 경계를 왜곡 없이
  정할 수 있다.
- **선택과 근거**: 사용자의 명시적 요청에 따라 `.git`만 보존하고 기존 추적 파일을
  모두 제거한다. 코드 재사용 여부는 새 상세 설계가 확정된 뒤 별도 태스크에서 판단한다.

### 결정 2: `tt`의 태스크 관리 구조를 이 저장소의 설계 게이트에 맞게 확장한다

- **상황**: 모든 작업을 파일로 관리하면서 코드보다 설계를 먼저 강제해야 한다.
- **검토한 대안**: 단일 체크리스트는 간단하지만 결정 근거와 작업 재현성이 약하다.
  `tt`의 인덱스·개별 태스크·템플릿 구조는 상태와 상세 기록을 함께 유지한다.
- **선택과 근거**: `INDEX.md`를 단일 진실 소스로 두고 `TASK-NNN` 문서를 사용한다.
  여기에 필수 설계 문서와 문서 준비 게이트를 추가한다.

### 결정 3: 프로젝트 자체 문서 체계를 사용하고 PRD 생성 스킬을 금지한다

- **상황**: 이 프로젝트의 PRD는 긴 제품 대화에서 확정된 고유한 도메인 결정과
  설계 선행 원칙을 보존해야 한다.
- **검토한 대안**: 범용 PRD 스킬은 일반 템플릿을 빠르게 제공하지만 피그마·Swagger
  중심 워크플로와 단일 구현 명세 형식이 현재 단계와 맞지 않는다.
- **선택과 근거**: `prd-generator` 스킬과 그 템플릿을 사용하지 않는다. PRD는 승인된
  대화, 저장소 문서와 태스크 의사결정만 근거로 관리한다.

## 이슈 및 해결

### 이슈 1: 샌드박스에서 Git 인덱스를 수정할 수 없음

- **증상**: `git rm -r -- .` 실행이 `.git/index.lock: Operation not permitted`로
  실패했다.
- **원인**: 작업 공간 정책이 `.git`을 읽기 전용으로 제공했다.
- **해결**: 사용자의 초기화 요청 범위 안에서 Git 인덱스 수정 권한을 승인받아 같은
  명령으로 정확한 추적 파일만 제거했다.
